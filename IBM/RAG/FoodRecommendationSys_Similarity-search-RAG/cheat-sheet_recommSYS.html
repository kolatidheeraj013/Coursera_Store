RAG Overview

Retrieval-Augmented Generation (RAG) improves language model responses by retrieving relevant external information before generating an answer. This helps reduce hallucinations and creates more grounded answers.

What problem does RAG solve?

  • LLMs have limited context windows.
  • Knowledge is frozen at the point of training.
  • Models can generate incorrect or unsupported information.

RAG pipeline

  1. Collect relevant source documents.
  2. Split text into smaller chunks when needed.
  3. Convert documents and chunks to embeddings.
  4. Store embeddings in a vector database.
  5. Receive the user prompt.
  6. Embed the user prompt.
  7. Retrieve the most relevant chunks.
  8. Combine the retrieved context with the query.
  9. Send the augmented prompt to the LLM.

Role of a vector database

A vector database stores and retrieves embeddings. It supports fast semantic search and keeps retrieval consistent with the source documents.

Common pitfalls

  • Using different embedding models for documents and queries.
  • Chunking documents poorly.
  • Forgetting to re-embed data after changing the model or distance metric.
  • Assuming retrieved content is always the best final answer.

ChromaDB

ChromaDB is a vector database commonly used in RAG systems to store embeddings and search for relevant content.

Create a collection

import chromadb
from chromadb.utils import embedding_functions

sentence_transformer_ef = embedding_functions.SentenceTransformerEmbeddingFunction(
    model_name="all-MiniLM-L6-v2"
)

client = chromadb.Client()

collection = client.create_collection(
    name="food_collection",
    metadata={"description": "Food dataset"},
    embedding_function=sentence_transformer_ef
)

Connect to an existing collection

collection = client.get_collection(name="food_collection")

Add documents

collection.add(
    ids=["id1", "id2"],
    documents=["Italian pasta", "Thai curry"],
    metadatas=[{"source": "food1"}, {"source": "food2"}]
)

Retrieve documents

results = collection.get()
results = collection.get(ids=["id1"])
results = collection.get(include=["embeddings"])

Update documents

collection.update(
    ids=["id1"],
    documents=["Updated pasta description"]
)

Delete documents

collection.delete(ids=["id1"])
collection.delete(where={"source": "food1"})

Distance functions in ChromaDB

ChromaDB uses a vector index with a configurable distance metric.

  • l2 - squared L2 distance
  • cosine - cosine distance
  • ip - inner product distance
collection = client.create_collection(
    name="my_collection",
    metadata={"hnsw:space": "cosine"}
)

Important note

Some collection settings, such as the embedding model or distance metric, cannot be changed after creation. In those cases, it is often easier to create a new collection.

What vector databases do not handle

  • Chunking text
  • Extra retrieval logic such as re-ranking
  • Prompt augmentation
  • Direct LLM integration

RAG frameworks

Frameworks like LangChain and LlamaIndex help connect vector databases, document processing, and model orchestration into a single system.

Key takeaways

  • Vector databases are essential for modern RAG systems.
  • They improve semantic retrieval and reduce implementation complexity.
  • Good document preparation and testing are critical for quality results.
